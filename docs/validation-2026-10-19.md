# 2026-10-19 修复、检索验收与跨模态决策

## 结论

上轮确认的登录校验、个人资料字段、公开邮箱和静态资源暴露问题已经修补。最终版本通过 **39 项接口/逻辑回归**及 **7 条真实 Chromium 浏览器流程**。本地词法检索的完整标题排序、长句漏检、单字误召回、关键词边界和有限排除条件也已修补。

**本轮暂缓引入真正的跨模态检索。** 固定诊断说明，修正文字检索就能解决一批已有问题；剩余误召回首先需要明确查询约束和可核验的内容依据。现有 16 条作品记录与 6 个视频链接，尚不足以验证真实镜头匹配。这个决定基于本仓库的实现与诊断结果，没有进行模型间效果比较。

## 修补内容

| 问题 | 修补后的行为 | 对应代码与验证 |
| --- | --- | --- |
| 登录模式把隐藏的姓名输入保留为必填，浏览器会阻止提交 | 登录时姓名隐藏、禁用且非必填；注册时同步恢复；往返切换也保持一致 | [登录逻辑](../js/main.js)、[表单回归](../test/auth-form.test.js)、真实浏览器原生校验 |
| 个人资料把已经转换的用户对象再次转换，丢失昵称和公开 ID | 直接使用认证中间件提供的账户输出，读取、保存、刷新后身份一致 | [资料路由](../server/routes/profile.js)、[后端回归](../test/backend-regressions.test.js) |
| 社区、好友和分享输出包含其他用户邮箱 | 公开身份仅输出 ID、公开 ID、昵称；本人认证与个人资料保留本人邮箱 | [用户序列化](../server/db.js)、社区/好友/分享路由及合成账户流程 |
| 整个项目根目录作为静态目录，数据库和服务端文件可落入公开访问范围 | 只提供指定 HTML 页面、CSS、浏览器 JS 和生成图片目录；合成数据库、源码、配置与路径穿越请求返回 404 | [静态资源白名单](../server/app.js)、实际创建 SQLite 文件的 HTTP 回归 |

检索修补集中在 [worksRepository.js](../server/services/worksRepository.js) 和 [搜索路由](../server/routes/works.js)：

- 原始完整查询匹配书名、电影名、作者或导演时优先。合成回归同时覆盖“我们”这类语法词标题，以及“不要…”“排除…”开头、未加书名号的标题，避免查询解析吞掉合法名称。
- 关键词分别归一化和计分，保留条目边界；用分词和通用语法词过滤替代短中文查询逐字扩展。库中已有的多字关键词可作为字面词表，没有增加针对诊断案例的同义词或修改种子内容。
- 原有主题关联词只对已有直接文字依据的结果作少量重排，不能单独产生候选。先检索整个作品集合，再截取最多 30 条结果，修复旧作品在新增超过 500 条后不可检索的问题。
- 支持句首、标点或“但 / 但是 / 不过”后的“不要 / 排除”子句；“没有寄出的信”等描述仍作正向文字处理。没有正向条件且没有同名元数据的纯排除查询返回空。
- 纯标点不触发外部搜索。带明确排除条件时只用本地记录，防止外部接口追加未验证约束的候选；普通正向查询保留原有外部资料补充流程。

补充了 [README](../README.md) 中的 Node.js 24 启动方式、后端连接要求、离线验收命令和数据边界。测试现在通过原生 CommonJS 加载应用与数据库，确保清理的是应用实际使用的 SQLite 连接。

需要保留的失败与观察如下：

## 是否引入真正的跨模态检索

**当前决定：暂缓，先完成内容依据与查询约束。** 这次长句改善来自现有文字的合理检索；颜色误召回和多个条件分散命中，也不能据此判断加入视觉向量就会解决。

下一轮按以下顺序推进更容易验证价值：

1. **让结果说明依据并处理约束。** 区分完整命中与部分相关，说明命中的字段/段落；对跨领域查询和多条件请求设定明确的返回规则，并保留本次失败样例作为后续检查。
2. **补充可核验内容。** 为文学文字记录版本、段落或页码；给文学与电影配对标注改编、灵感来源或氛围联想。对准备检索的视频建立可访问来源、镜头起止时间、代表帧和内容标注。视频链接与生成海报本身都不能充当这套数据。
3. **用新查询比较文字方法。** 若有依据的段落仍因同义表达被漏掉，再用固定的新标注集比较当前词法检索与文字语义检索，分别记录找对作品、找对段落、空结果误召回及成本/延迟。
4. **在需要画面证据时做跨模态试验。** 当用户需要“凭截图找片段”或检索文字元数据未描述的颜色、动作、构图时，再比较文字到真实帧/镜头、图片到段落的方案。验收对象应是实际镜头和可核验片段，单独判断新增视觉信息是否带来收益。

本轮没有加入新的模型密钥、嵌入服务或视觉索引。真实跨模态的技术选型，应由后续可核验数据上的效果比较决定。

## 复现

完整启动说明见 [README](../README.md)。在修补分支、Node.js 24 环境中运行：

```bash
npm ci
npm test
npx playwright install chromium --only-shell
npm run test:browser -- --output /tmp/ameets-browser.json
npm run evaluate:retrieval -- --output /tmp/ameets-retrieval.json
npm run evaluate:retrieval -- --fixtures test/fixtures/retrieval-holdout-cases.json --output /tmp/ameets-supplement.json
```

浏览器依赖系统可能还需安装 Chromium 的系统库。检索诊断默认输出失败样例但退出成功；加 `--strict` 时，当前保留的能力探查失败会使其返回非零，不应误报为全量通过。基线复现应在独立目录检出上述基线提交，再放入本次相同的评估脚本和固定查询；不要用修补后的检索文件冒充基线。

紧凑 JSON 存档保留查询、判定、排名、作品标题和来源指纹，省略每次重复的摘句与描述。脚本的 `--output` 可生成完整载荷。所有结果仅说明所记录的本地版本及测试范围，不等同于线上部署或外部服务验收。
