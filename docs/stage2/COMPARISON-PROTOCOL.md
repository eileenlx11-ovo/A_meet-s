# 下一阶段：先建立内容依据，再比较检索方法

这是拟执行协议，不是已完成实验；下述规模和门槛是本项目工作建议，不是文献结论。当前没有运行文字语义、重排或视觉模型。

## M2b：把来源台账变成可核验小集合

先选三至五个作品，逐条核对其中少量段落，而不是批量用生成文本填满数据库。每条需要文献身份、语言、版本、译者（如适用）、章/节、可重定位段首或实际页码、最短必要摘录及哈希。把“原文摘录”“出版译文”“编辑概述”“用户描述”分开保存。对未能核验的原 `quote` 不补造版本；保留警告或从正式引文展示集合移出。

“原文已定位”“中文翻译核对完成”“作品级改编”“同一段落/同一镜头对应”是四个不同状态，不得逐级自动推导。当前 `quote` 始终为 unverified 是有意的安全默认值；日后允许 verified 时须另外实现字段、证据要求和对应迁移测试，不能只删除前端警告。

## M3a：文字检索比较的进入条件

准备一批来源可核验的段落，并由实际阅读者写下查询与相关性判断。可从 30–50 条段落、40 条新查询开始试验；这只是起始建议，不能据此声称统计显著。新查询不能都来自当前样例的改写，标注前不观察模型输出。

查询至少区分完整名称、明确视觉/氛围条件、同义表达、否定与多条件、无答案和跨领域意图。每个查询标注“必须”“可选”“排除”的条件、支持它们的段落及哪些需求没有证据；主观氛围可有多个合理答案，争议样例留给人工评议。

### 固定对照

1. 当前字面检索和约束过滤，作为可解释基线。
2. 在相同数据上增加有来源/人工确认的受控别名与表达规范化，判断简单改进是否已经足够。
3. 在同一集合上试验文字语义候选召回；必要时再比较重排。语义分数只说明模型相关性，不是引用出处或条件满足的证据。

模型选择、版本、运行环境与预算在真正开展时核对再固定。本轮不指定未经当前环境测试的模型、API 或安装命令。保留相同候选数量、相同数据、独立评测查询；不在评测集上手动调到全部通过。

### 记录内容与决策

分别报告候选覆盖、Top-k 相关性、多条件违例、错误的“完整命中”比例、无答案误报、人工解释是否有原文依据，以及延迟/实际费用。主要命中与部分候选分开统计；不得把“仍能在候选区找到”计作完整答对。

只有在独立查询上改善同义表达召回、同时没有牺牲硬约束与来源可核验性时才推进语义方案。当前六条从主要结果降为部分候选的自然表达，是错误分析素材，不是模型获胜的预设证明。样本不足或差异不稳定时，报告不确定性，不宣布模型优越。

## M3b：真正跨模态比较的进入条件

需求应具体到文字难以可靠覆盖的视觉任务，例如“用截图找到同一镜头”或“同一镜头中同时出现雪地和绿色裙子”。先有真实、可使用的媒体与标注，再比较视觉方法，不把作品海报/字幕/标题检索包装成镜头检索。

逐条处理 `data/video-annotation-queue.json`，至少保存：具体媒体来源及使用范围复核、文件 SHA-256 与时长、起止秒、区间内代表帧、镜头内容描述、对象/颜色/动作标注、观看复核人和日期。时间必须针对同一媒体版本；不能从不同剪辑或发行版搬用时间戳。模糊、无法播放、版本不明的条目不能作为评测真值。

结构校验 `validateSegment` 只检查字段完整性和时间合法性。它不检查画面，不核实复核人的真实性，也不替代使用许可判断。现有数据中的 0 条真实镜头仍应保持 0，不用测试合成条目填充。

媒体准备好后，同样固定查询与真值，对比：文字描述/字幕基线、代表帧图文检索、必要时视频级或时序方法。测试集合要包括字幕出现但画面不存在、颜色相同对象不同、条件分属不同镜头、同一作品不同版本等困难负例。只有这些任务显示稳定收益，才考虑把跨模态作为产品主能力。

## 集成发布门槛

第二阶段仍应在完整 PR 仓库和项目声明的 Node 24 环境下跑全量 API、实际登录/作品页 HTTP 流程及已有七条站点冒烟。离线 DOM 组件通过不能替代部署验证。PR #1 未合并时，第二阶段 PR 以它的分支为 base；PR #1 合并后再核对内容并重新定基，不直接推 main 或自动部署。
